PASOS CONTROLSTOCK EN LA NUBE
=============================
Actualizado: septiembre 2026

ESTADO EN PLANTA (hoy)
----------------------
- MODO LOCAL (PC servidor + SQLite + WiFi).
- Modo nube: IMPLEMENTADO en la app, NO activado en producción.

Hay DOS partes:
  A) Configurar el servidor en la nube (ej. Railway)
  B) Configurar la app (PC / APK) y migrar datos

Guía corta: docs/CONEXION-RAILWAY.md


================================================================
A) RAILWAY — crear / revisar el servidor
================================================================

A1. Entrar a Railway
- https://railway.com

A2. Proyecto + código
- New Project → Deploy from GitHub → repo bodegaStock
- Rama: main
- Railway construye con el Dockerfile del repo

A3. Variables del servicio API (Settings → Variables)
- JWT_SECRET = clave larga inventada
- BODEGA_DATA_DIR = /data
- DATABASE_URL = referencia al Postgres del proyecto

A4. Base Postgres
- New → Database → PostgreSQL (mismo proyecto)

A5. Conectar Postgres a la API
- Servicio API → Variables → DATABASE_URL = ${{Postgres.DATABASE_URL}}

A6. Dominio público
- Settings → Networking → Generate Domain
- Usar https://xxx.up.railway.app (NO .railway.internal)

A7. Probar
- https://TU-DOMINIO.up.railway.app/api/health → ok
- Logs: DB: Postgres (DATABASE_URL)


================================================================
B) APP — apuntar a la nube y migrar (cuando decidan el corte)
================================================================

IMPORTANTE
- Migrar desde la PC que tiene la base buena (servidor local).
- Hasta el corte pueden seguir en Red local sin problema.

B1. PC servidor — Configuración → Nube
B2. Pegar URL → Probar → Guardar
B3. APK: login → Nube → misma URL o QR
B4. Migrar datos (admin) → escribir MIGRAR
B5. Verificar login y stock
B6. Otras PCs/APK: misma URL nube

Si algo falla → volver a Red local (SQLite del PC no se borra)
